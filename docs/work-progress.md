# 工作進度布告

耗時工作開始時，上方布告會顯示工作名稱、目前階段、動態進度條與已用時間。
有可核對的總數時才顯示百分比，例如深入分析的完成項目、清單已處理篇數、
PDF 簡報已繪製頁數。等待模型回覆時使用動態等待條，不預測剩餘秒數。

「工作」選單列出本次開啟 app 的最近工作；將滑鼠停在階段文字可看最近階段。
同一入口執行中不會再啟動一份工作。清單綜覽即使關閉再開視窗，仍共用執行狀態。
對話視窗內也顯示進度，避免被視窗遮住。

完成時，若你還在原來的位置且沒有繼續操作，焦點會返回產出區。若已切換論文、
清單或正在輸入，則保留目前位置，從布告的「查看結果」回到工作結果。
部分完成、失敗與停止會分開顯示；失敗原因保留在原操作區，可修正後重試。

目前串接：共用 AI 問答／翻譯／研究問題／簡報生成與改寫、Google Slides、
單篇與清單分析、清單綜覽、研究清單建立、研究資料包匯入匯出、單篇 PDF 準備、
PDF 簡報匯出與攜帶閱讀頁。清單背景下載的短進度條仍在各篇標題列，方便逐篇辨識。
定時帳號資訊查詢不占用這個工作布告。進度與最近工作只保留在記憶體，不會回傳後端。

開發串接使用 `desktop.activity.begin()`，在共用 `AskRunner` 中已自動註冊。
背景函式可以呼叫 `work_progress.report()` 提供階段，並在有實際計數時附上
`completed` / `total`。子程序需開啟 `PAPERFACT_PROGRESS=1` 與 UTF-8 非緩衝輸出；
這是明確的進度事件，不是模型的思考內容。完成回呼須先保存並驗證結果，才結束工作。

驗收使用隔離資料庫與模擬模型／子程序；實際外部帳號生成不是壓力測試的一部分。
