# Temporary statement comparison

Status: integrated local v0.5 UI candidate, not release or scientific evaluation evidence.
The complete integration/full gate and physical-device acceptance remain separate.

Evidence checks offers **Compare statements…** in its existing action row.
Opening reads the existing captured output selection and Audit route in a local
worker; it does not ask a model. Both the audit launch and comparison child are
modeless. Researchers can read and type unsent questions/notes during a call.
Explicit account/model settings may use the existing transient modal picker.

Select 1–8 actual captured outputs, then explicitly Generate. The existing Audit
connection snapshot is captured on the worker. The immutable job uses one facade
completion with a 4,000-token output budget setting, even if its configured
budget is larger. Actual enforcement depends on the service; current CLI adapters
do not enforce this setting. A smaller/invalid configuration or oversized selection fails
without a silent clamp, fallback or automatic retry. Existing provider transport
policies are unchanged; one facade call is not a promise of one HTTP transmission.

The copyable temporary text includes source identity, proposed facts, attribution,
scope, values, rounding/derived/unknown distinctions, both captured output locations,
and requested/reported model IDs. Missing reported identity stays unreported.
No scientific contradiction, semantic support, formal proof, quality score or
complete-paper absence is certified. A located quotation is only a location check.
No report, note, fact sheet or new source authority is persisted or synchronized.

Preparation, extraction, PDF/quote work, source SQL, sheet/result current checks
and text rendering run on the owned worker. GUI delivery checks the original
window/view/document identity and native DB/WAL/PDF observations plus a private
configuration/environment lease. Full configuration/environment scope is never
rendered, serialized or logged. Source buttons reverify the accepted sheet and
actual loaded original on a worker before the existing native navigation callback.
They never resolve an old reference to the desired/new primary PDF.

A pending route/context change rejects late installation and keeps the prior
temporary report. Changing the next model after acceptance does not rewrite that
report's provenance or document identity. Its source check is independent of the
future model preference. Parent capture changes mark the old view stale; reopen
explicitly instead of silently renewing its authority. Closing, update and restart
retain the worker/capture until actual thread join and GUI install/discard finish.

## Existing limits

- `AuditCapture.current()` retains its conservative physical DB/WAL fence.
  During a pending comparison, an explicitly captured reading owner permits one
  bounded read-only recapture only if the original owner, source bytes, complete
  captured research state and selected outputs still match. It makes no second
  model call. Changed notes or source bindings reject the result. Later writes
  after acceptance can still invalidate source navigation; the temporary report
  remains visible and copyable. See [reading continuity](audit-reading-continuity.md).
- The existing routing revision observes saved settings and process environment,
  including credential selection encoded there. It does **not** observe vendor
  CLI reauthentication inside an unchanged private credential home. No token-file,
  vault, auth-status or remote-account probe is added. Configured intent is not
  an authorization claim.
- Source material remains bounded text extraction. Unseen figures, exhaustive
  literature retrieval and scientific precision/recall require separate evidence.
  Derived values are not recomputed. Unknown original bindings stay unknown.
- Temporary reports are not recovery artifacts. Copy desired text before closing;
  reopening does not restore a generated report or replay a prior operation.

The fixture gate uses actual isolated SQLite/PDF/native Qt navigation and fake
completions, including modeless typing, cancellation, stale context, route/env
changes, close/update/restart ownership and explicit empty/error outcomes. It is
software behavior evidence, not scholarly accuracy or production-service acceptance.
