# Common proposal recovery

This isolated change carries complete local and enrolled scientific proposals
through FULL backup, detached restore, and an explicitly prepared fresh editable
workspace. It does not replay source operations, writer observations, native
identities, or process seals.

## User-visible sequence

1. FULL backup preserves the exact scientific deck, full evidence, all declared
   used/unused/evidence-only PNGs, and exact original PDFs. Unknown protocols,
   incomplete closures, foreign owners, and source changes refuse the backup.
2. Detached restore archives the original catalog rows as provenance. The content
   carrier is not a native proposal. A fresh editable copy publishes fresh target
   originals and stores the complete content in its actual artifact CAS.
3. Review lists one archive-backed entry. Preview displays its scientific content
   without applying a deck. Explicit Verify captures the final receiver target,
   mapping, parent epoch, native database, transfer binding, and source witnesses;
   it creates one inactive native proposal plus one stable archive link atomically.
4. Repeated Verify and restart reuse that native proposal. Apply remains a separate
   confirmed existing Review decision with a fresh displayed active-deck base.
   The complete scientific catalog remains independent of the used-figure wire
   projection. A changed/deleted/recreated target never inherits the source owner.

## Current PDFs and manual decks

A genuinely unbound sender with common local proposals can retain its current
canonical primary B separately from retained original A. The observer uses the
actual DocumentReader and existing parent lifecycle. It never creates a source
owner, binds the sender, or substitutes B for A.

Plain manually saved current decks in the canonical `presentations` directory
have a separate closed archive-only format. It preserves exact saved JSON,
canonical immutable asset PNGs, optional actually saved evidence, and exact
referenced originals. Used images must exist. Dormant metadata without an asset
remains metadata; device paths are never followed. No model/revision receipt is
invented. Detached reading validates this closure and grants read/export only.
Fresh current-deck publication uses unknown/incomplete input versions. The full
original JSON remains archived even when the maintained active wire sanitizes
device fields and projects only used figures.

The newly authored audit fixture originally configured a unit-test-only `decks`
root. Its supported journey now performs an ordinary public manual save into the
canonical `presentations` root before owner capture. It preserves every actually
saved field; no AI revision is created. The unused figure's cache-path placeholder
had no saved PNG. The common proposal independently retains its three scientific
figures plus the fourth evidence-only PNG.

## Bounds and refusal

The frozen common carrier/codec retains its existing limits. Observed manual
slots allow 8 MiB JSON objects, 128 declared PNGs (8 MB each; 64 MiB aggregate),
16 PDFs (150 MiB each; 512 MiB aggregate), 2,000 slots, and 768 MiB unique staged
objects per collection. Native tree enumeration is bounded. Exceeding any bound
fails; no truncation occurs. All native handles are explicitly closed. Known
staging junctions/symlinks are rejected before any write.

## Evidence and limits

See the source-only handoff result for exact per-run source hashes and counts.
The original two-case audit assertions stay unchanged; approved changes are new
fixture setup/public-call admissions. New controls cover source/native/asset
changes (including a missing PDF appearing late), cancellation, real NTFS
junctions, repeat/restart, SQL rollback/retry,
initial enrollment, and separate explicit Apply. All inputs are disposable and
the new fixtures deny provider/network/process launches. The maintained CLI
recovery test invokes only isolated local Python recovery commands.

This is backend integration evidence, not a full-suite, UI, live-device, or
release claim. Arbitrary presentation roots, unrepresented historical/manual
files, and separate confirmed reattachment of retired source-parent proposals
remain unsupported and refuse rather than silently disappear. First-enrollment
coverage with a common proposal and no prior active deck is separately tested;
manual-current first-enrollment migration is not claimed by that scenario.
Existing strict revision/raw-draft/unknown-schema guards stay active. The old
unapplied lineage recovery/review patch is excluded.
