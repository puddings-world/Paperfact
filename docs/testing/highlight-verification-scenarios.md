# 原句位置核對與獨立閱讀：A、B與修改資格分開

2026-11-02 · `0.5.0.dev` · 隔離整合候選，未發布。

**新的螢光筆核對與原文讀取是後端服務；整組套用、原生修訂介面及CLI／MCP仍待接。**
本輪沒有把核對成功當成研究解讀正確，也沒有自動發布人工修改。

## 四個具體情境

| 真的怎麼操作 | 必須觀察到什麼 |
| --- | --- |
| 目前讀B，修改A私稿的理由／角色，再核對原句並讀A | 原句位置與人工報告正確；正式研究／待送資料不變，B仍是目前原文 |
| 改成不存在的引句、錯誤頁碼或舊座標，再核對 | 保留問題狀態，不產生半組可套用標記；A仍可閱讀以便修正 |
| 核對後重開、換人工稿、撤銷核對或更改標記 | 舊結果不冒用；獨立閱讀已保存的A不等於取得修改資格。精確私稿版本參照不偷偷跟到新版 |
| 私稿備份、唯讀恢復、移走舊資料夾、接管後選目標，再讀A及核對 | A的位元組、文字及來源保留；不靠舊路徑，也不發布研究 |

明確退役的A不改讀B或偷偷使用快取；需要另行明確恢復來源。
保留分析的來源文字記錄與真正A不符時，即使引句看似合理也拒絕核對成功。
GUI快速檢查禁止SQL、PDF解析與內容雜湊；螢光筆讀取資格不能當成主張資格。

## 與先前私稿服務的關係

私存保留人工內容；核對查A及目前接收目標；獨立讀取只授予這份A的閱讀；
套用修改仍是另一條待完成的確認與交易。保存核對過的預覽，私稿裡的`apply`仍為false；
重開需要重新核對。本輪共用原文讀取邊界保留原有主張入口，並回歸其真正Qt、CLI與官方MCP路徑。
這些舊工具測試不代表新的螢光筆工具已註冊。

最初新情境因測試未沿用註冊的附件版本目錄而在準備階段失敗；修正準備後確實因缺少核對入口而失敗。
先前21項核對／主張來源、4項新邊界與1項恢復旅程已各自通過；它們與上述最終回歸重疊，不相加。
沒有改鬆既有測試。
