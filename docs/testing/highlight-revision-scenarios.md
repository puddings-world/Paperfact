# 重點修訂與素材跳轉：這輪實際做了什麼

2026-11-02 · `0.5.0.dev` · 隔離整合候選，未發布。

## 現在能觀察到的改善

正式讀取器按「查看重點素材」會等待該次背景整理，完成後選取正確素材並定位原句。
連按不另開工作；等候中改選素材、切分頁或收起面板，就取消自動跳轉。
整理失敗保留現有素材，重新按下可明確重試，不會先跳到舊素材。

人工修改重點的內容核心也已實作：修改引句、理由、角色或頁碼提示後，從同一版原文重新找位置。
**這個核心還沒有接上私稿保存、重開、完整備份恢復、正式套用或操作介面。**
不能把內容核心通過稱為整個重點修訂功能完成。

## 用操作看測試

| 實際做的事 | 檢查留下什麼 | 不代表什麼 |
| --- | --- | --- |
| 正式讀取器畫重點，暫停整理，連按12次，再放行 | 一次整理；完成才選到同一標記與原句；未存筆記保留 | 不是12次AI分析 |
| 等候中改選素材、離開分頁或收合面板 | 不晚跳回原重點、不搶回閱讀位置 | 不保證所有舊畫面刷新已全面改良 |
| 整理失敗一次，再明確重試 | 舊內容保留；第一次不跳，第二次定位成功 | 不會偷偷重跑AI |
| 改引句為不存在或出現兩次的句子 | 明確缺失／歧義；不輸出半組可套用標記 | 找到句子不等於研究解讀正確 |
| 指定重複引句的第二個實際位置 | 使用明確位置，不自動挑第一個 | 不是AI挑選研究重要性 |
| 目前原文換成B，核對已擷取的A | 仍核對A；B不冒充舊稿來源 | 核對結果不等於套用研究的許可 |
| 以固定回覆跑真正HighlightJob，再準備人工修訂 | 來源、位置、涵蓋保留；原分析／標記／待送資料不變 | 不驗收真實模型或學術品質 |
| 舊讀取器標記損壞、過大或來源已改 | 拒絕更新並保留畫面；不降級繞過正式來源核對 | 相容預覽不是獨立歷史原文資格 |

## 發現過什麼問題

新正式讀取器案例先重現「整理完成但原文沒有選中」而失敗，修正後納入上述凍結檢查。
先前相關檢查也重現舊讀取器素材未選取；相容預覽與正式來源資格分開處理。
新超長輸入測試一度把內容放進pytest參數名稱，超出Windows環境變數限制；改短名稱，
超長輸入與原斷言全部保留。沒有改鬆既有測試。

## 距離完整接續還缺什麼
