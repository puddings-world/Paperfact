## 四條可以讀懂的操作

| 真正怎麼操作 | 必須看到的資料結果 | 未涵蓋 |
| --- | --- | --- |
| 改A的引句／理由，核對全部原句，再明確確認套用 | 分析與完整標記共同保存；手動畫線與隱藏選擇保留；B不切換 | 沒有新的原生編輯畫面，原句位置正確不代表理由成立 |
| 故意讓第二筆標記或決策儲存失敗，再重試 | 失敗不留半組資料；來源、研究、私稿與待同步操作一起回滾；修復後只存一次 | 不是隨機損毀測試或實體斷電驗收 |
| 八次並行送出、取消、改稿或換資料庫 | 相同請求只提交一次；取消或來源／目標過期時拒絕，較新研究不被覆蓋 | 不是八次AI呼叫；新介面工作執行緒仍待接 |
| 兩份私稿備份、移走舊資料夾、接管，套用後傳同儕離線隱藏／加筆記，再同步與備份 | 私稿內容、A／B、研究、隱藏狀態及筆記保存；舊套用重試不覆蓋回來的新修改 | 本機參考服務與獨立資料庫，未跑Windows／Mac／手機安裝版 |

真正遠端分析衝突也有獨立案例：人工比較後確認，解析操作指向正確的分析衝突；
兩端收到同一份分析與完整標記，重試不重複。單筆標記不能冒充完整分析來源。

## 新測試曾經暴露的設定錯誤

先以缺少`apply_highlight_draft`重現失敗。新測試的第一次全檔執行22通過／2失敗：
分析故障注入用錯INSERT（真正更新使用UPDATE），另一測試在開始交易前就建立操作。
修正新測試設定，原資料保存／回滾斷言保留。
恢復流程會重新發布正式分析的來源，因此不能把同一份A叫作「尚未發布的私有來源」。
改由真正HighlightJob產生不同於正式來源的待處理A，再證明來源與研究共同回滾。
本地參考服務也明確配置附件儲存。這些是測試設定修正，沒有改鬆舊測試。
第一次維護檢查36通過／1失敗：新旅程把其他PDF版本的歷史標記也誤當隱藏目標。
修正為逐筆比對「只隱藏所選的一筆，其餘所有歷史標記不變」，再取得上面的完整相關範圍結果。
