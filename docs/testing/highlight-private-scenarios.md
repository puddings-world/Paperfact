## 三條實際資料旅程

| 怎麼操作 | 實際檢查的結果 | 還沒證明什麼 |
| --- | --- | --- |
| 從真正保留分析保存兩份理由／角色不同的人工稿 → 關閉 → 重開 | 兩份文字與原觀察保留；正式分析、手動畫線、AI標記、同步佇列不變 | 沒有核對或套用到正式研究 |
| 私存 → 備份 → 唯讀恢復 → 移走舊資料夾 → 建立新可編輯副本 → 明確選目標 → 再私存 | 文字與原文來源雜湊保留；唯讀副本不寫入，新稿綁新工作區 | 尚未完成恢復後查原文／套用／另一裝置編輯再回來的整條旅程 |
| 兩份資料庫透過本機參考服務造成真正衝突 → 禁止服務呼叫 → 私存重開 → 遠端再更新 | 比較內容及離線文字保留，新更新後舊稿變stale；單一標記不能當整份分析 | 不是實體Mac、手機、正式雲端或團隊協作驗收 |

## 常見意外怎麼測

- 十次並行保存同一識別，只留一份第一版；第二視窗不能覆蓋較新私稿。
- AI標記隱藏／刪除、手動畫線或分析內容改變，私稿保留並要求重新核對。
- 無關筆記不偷偷換基準；明確重選目標時人工文字保留。
- 保存後、提交前故意失敗：整筆回滾；同一草稿／請求可重試。
- 新工作尚未允許時關閉就拒絕；已允許保存可收尾，不丟人工文字。
- 錯誤格式、重複JSON欄位、偽造資格、過大資料和真正換掉資料庫，都不寫錯位置。
- 舊素材A收尾時，B的新查看請求仍會執行；使用者取消B跳轉後，A不能把它喚回。
