# Restored research: actions, outcomes and evidence

Updated 2026-11-01. Isolated unreleased integration. This page describes actual
public-service fixtures and visible Qt actions; it is not a release certificate.

## Reader workflow

1. Create a FULL backup and restore it into a detached workspace.
2. Explicitly prepare a fresh editable copy. Prior current deck and PDF B remain
   separate from the retained scientific proposal and its original A.
3. Open retained-work Review. Sources and all four image captions are inspectable.
   The original-open control explains that Verify is required first.
4. Verify creates one inactive proposal owned by the actual final receiver. It
   does not replace the active deck or publish a synchronization operation.
5. Open exact original A in a separate read-only viewer. Reading does not change
   research rows, PDFs, CAS bytes or the selected primary PDF B.
6. Cancel or explicitly confirm Apply. Only confirmed Apply publishes the deck;
   full unused scientific material remains retained separately.

These are four test functions, expanded across real local/enrolled senders and
selection/close variants into ten cases. They use real disposable backup/restore,
SQLite, CAS and Qt. Provider/network/process launches are denied by the fixtures.

## Limits and next work

The original two-case backup audit's 23 Assert ASTs are unchanged. Six shared
recovery-module changes stay within the declared handoff scopes; local preview
source metadata is preserved. Unknown protocols and incomplete/foreign ownership
remain strict refusals, not silently omitted research.

ordinary slide-canvas/material navigation, retired-parent reattachment, all
rescue carriers, or deployed/physical-device acceptance. Detached content is
archive-only; it is not receiver ownership. Installed Apple Silicon Mac, phone,
real account and scientific-quality checks remain separate.
