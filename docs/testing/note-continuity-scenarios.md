2026-11-02，`0.5.0.dev` 隔離候選版，尚未發布。
兩條完整資料流均通過：**2 通過、0 失敗／錯誤／跳過**；119.84 秒測試／121.25 秒整輪。
執行中 976 個程式與測試輸入零變動。新增的只有這份測試檔；前輪 88 項的所有 975 個程式／測試輸入仍逐一相同。
兩輪是不同範圍，沒有把它們包裝成整版或同一次 90 項驗收。

## 1. 私稿換機恢復後，重新核對原文再套用

本地 agent 已保存私稿，但尚未改動正式筆記；目前閱讀 B，草稿使用 A。

**實際操作：** 保存含原文位置的私稿 → 備份 → 唯讀恢復 → 建立新的可編輯副本 → 明確選目標 → 核對 A → 確認套用 → 再次備份恢復。

**實際結果：** 文字、A 的 PDF 位元組與引句位置保留；讀取舊資料夾被禁止仍可完成；原機正式資料不變。舊草稿 ID 不能直接使用，舊重試收據只留在歷史，新工作區必須重新開啟核對。

1/1 通過；78.07 秒，包含資料準備與收尾。

## 2. 離線修改回來後，舊套用重試不能蓋掉新文字

agent 已套用的筆記與 A 傳到第二份獨立資料庫，該裝置仍在讀 B。

**實際操作：** 傳遞筆記及 A → 不連服務先修改 → 重建客戶端模擬重開 → 重連同步回原機 → 重送舊套用要求 → 備份恢復。

**實際結果：** 離線文字與待送佇列跨客戶端重建保留；重連後原機收到新文字。舊重試只回傳先前結果，不覆蓋新文字。A 位元組和位置仍正確、B 仍是目前原文；私稿及重試收據不會傳到同儕，備份保留研究與歷史。

1/1 通過；41.09 秒，包含資料準備與收尾。

## 這次沒有驗證什麼

第二條在同一台 Windows 上使用兩份獨立 SQLite、本機參考服務與真正檔案傳輸；沒有連線時先存筆記，然後重建客戶端再同步。
不是兩台實機、程序強制斷電或 Mac／手機測試，也沒有正式登入、正式雲端或真實 AI 呼叫。
正常備份／接管／重試已驗證；所有其他研究格式、故障中斷組合、完整歷史／保留政策與平台安裝包仍須驗收。

時間包含製造原始衝突、多次備份與獨立恢復，不是 App 每次按鈕延遲。
沒有重跑前輪 88 項；它們的程式與測試內容逐一未變。整版完整檢查仍未通過，不能提交或發布。
