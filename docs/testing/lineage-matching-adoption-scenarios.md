# Exact-content Lineage adoption behavior map

All research, PDFs, models and workspace identities are synthetic; no paid model,
real login, owner research or network service is used. Fake completions fail if
called, so saved-result adoption cannot silently regenerate science.

| Outcome | Observable acceptance |
|---|---|
| Match and preserve | Actual validated package matches a legacy-only corpus; model, scientific row, source hashes and timestamp stay identical while one native history/operation is added. |
| Retry | Repeated apply and re-prepare with the same decision return the prior action, leaving research/outbox/history unchanged. |
| Keep/cancel | Cancellation preserves all SQL; default Keep retains private science without a native marker. |
| Decision scope | Forged review seals and SQL changes invalidate approval without writes. |
| Late writer failure | Failure after actual typed publication restores the consumed private row and rolls back history/outbox/receipt; fresh retry succeeds. |
| Changed final target | Changes after preview are preserved; apply refuses instead of overwriting. |
| Independent recovery | Adopted row/history and three exact originals survive create/inspect/detached restore, without reactivating native identity or source grants. |
| Real peer | Ordinary upload/sync/receive retains the adopted row and all three exact original PDFs. |
| General replace flag (2) | Both replace flag states still require explicit adoption; replacement permission cannot be substituted. |
| Different report | Changed scientific content has neither adoption nor unowned replacement permission; the old approval cannot be reused. |
| Native authority (3) | Pending journal, retained history and lost marker on an already native report all refuse private adoption. |
| Selected parents (3) | Missing/mismatched actual materialization refuses adoption; the sealed review also binds changed parent incarnations independently of science text/mapping. |
| Late cancellation | Cancelling after the actual private-row removal restores the complete transaction. |
| Actual Qt comparison | Default Keep, identical texts and visible source quotations; adoption is a separate choice; rejecting writes nothing. |
| Two-stage apply | Explicit comparison selection still needs final Import;20 clicks create one scientific history entry. |
| Close before final import | A reviewed preview can be closed without publishing private science. |
| Pending desktop action (2) | Closing drains a held worker, workspace switching refuses it, original SQL stays exact and the other database is not created. |

Independent recovery and actual rollback-baseline audit each add one case (23 new
cases across these five files).
These use real archive/PDF and native journal validation, not handler-call assertions.
Exact terminal receipts are kept in the continuation ledger. Old comparison,
package, projection and lifecycle tests are run unchanged in affected scopes.

The generic native projection still rejects an unowned SQL row. No broad store
permission or portable authorization token was introduced. This proves the
original-complete matching-package route only. Direct source selection without
a package, native corruption repair, arbitrary historical restoration, full
semantic audit and full/release/installed-device/hosted gates remain open.


A held workspace-switch action exposed a shared GUI error-path bug: the data
write refused correctly, but the old Review control remained enabled. The
package-review view now uses one stale-result handler for both successful and
failed worker delivery, including an already-committed result. The regression
requires both old controls disabled and exact original SQL preserved; its
expectation was kept unchanged while correcting the source.


The broader unchanged regression selection exposed an existing error-copy mismatch
(`caller transaction` was missing from initialization's refusal); source copy was
corrected without changing its assertion or transaction rule. It then exposed an
old rollback assertion expecting native metadata tables to be absent even though
generic native preparation had already created them before the action. The old
test is retained and remains a reported conflict. The separate baseline audit
compares complete SQL/schema before and after a real late protected failure;
it cannot substitute for resolution of that old contract or a full gate pass.

The first recovery fixture omitted the backup API's explicit owned BlobStore.
It correctly refused referenced bytes. The fixture now passes the actual native
importer's registered owned store; the ownership guard remains unchanged.
