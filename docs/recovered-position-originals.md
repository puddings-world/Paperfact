# Position originals in editable recovery

Editable adoption stages position originals before ordinary enrollment inventory.
The private baseline transaction captures a fresh receiver owner through the same
caller-owned highlight-owner factory used by the reader. It retains immutable
version-2 private source pairs and records receiver-local ownership beside the
canonical position. It does not create reading actions, reuse sender receipts,
replace the primary PDF, activate a workspace, call AI, or upload research.

The input must be the service's unchanged native sealed inspection. Every position
requires its active original paper lifecycle and readable exact PDF/page closure:

- Enrolled sources require the exact active desired `original_source` under the
  current mapped paper incarnation, including its closed body and PDF bytes.
  Missing, retired or mismatched portable ownership cannot fall back to a cache.
- Unbound sources require a typed current SQL position-owner record matching the
  original paper epoch and its exact backed-up private source receipt. An archived
  record, filename or matching hash alone does not grant receiver ownership.

Original requests, owners and protocol history remain validated archive evidence.
Receiver cache publication happens only in disposable private staging; cancellation,
changed research or failed storage cannot publish an editable/backup pair. Retrying
uses a fresh staging transaction. Changed original bytes require fresh inspection.

The joint regression uses a four-page original A with a page-three position, a
distinct two-page primary B, Inbox current/deleted/conflicting history, a curated
queue pin and its import history. Both enrolled and unbound-to-enrolled journeys
exercise two complete backup/detached/editable cycles and exact history equality
through maintained provenance readers. The snapshot/parser checkpoint supports
closed schema-2 positions alongside Inbox/queue-pin capabilities; schema 1 and
incomplete source ownership still refuse. These are local fixture guarantees,
not physical-device acceptance or a release claim.
