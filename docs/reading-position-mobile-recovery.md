# Exact-source mobile reading positions

The isolated reader now activates a bilingual Reading position dialog from the
existing PDF card. It supports explicit entered pages, exact original variants,
private page drafts, and bounded recovery import/review. Parent integration and
the combined full check remain required. This does not establish acceptance on
an installed PWA, a physical phone, or a hosted service.

## Reading position controls

The main form asks for an exact original and a manually entered page. A real byte
and PDF page-count check enables Remember; metadata and sender counts cannot do
so. The default status shows the verified count. Full native-viewer limitations
remain in collapsed PDF help, and the short hash is a secondary identifier.

Earlier originals and saved pages remain distinct from the current original.
Current C arriving does not replace a still-owned selected B or erase entered
text. An explicit PDF link opens owned verified bytes; it makes no native jump
or viewport claim. A unique kept page draft reopens on its exact original. Keep
draft persists privately, while Discard is explicit. An invalidated context
keeps uncommitted text visible and disables old-scope admission.

Counts and storage actions are single-flight. Cancel and close drain owned
workers, suppress late delivery, and preserve draft decisions. Raw reader note
drafts block navigation/Remember and remain unchanged. Superseding background
reads preserve the initial requested count, and a delayed note status update
cannot misreport a committed draft when the note tab is no longer present.

A typed creation receipt is required to label a known deleted page. Remembering
it again requires Cancel-first explicit confirmation and a fresh incarnation.
An unproven tombstone remains read-only. Imported snapshots remain read-only
until current workspace history supplies actual authority.

The collapsed recovery area retains imported originals and proposals privately.
Review requires the current authenticated binding and a fresh real byte/count
check. Archived ordinary note, draft and outbox text is explicitly read-only,
viewable as literal text, and exportable. It is never generically queued.

## Source and publication boundary

A verified accepted `paper_document` receipt, its exact paper incarnation, and
independently parsed PDF bytes can prepare a primary original. Only an explicit
entered save or page-draft intent admits private retention. Merely opening or
counting a primary creates no source operation, position operation, or private
retention entry.

The atomic local save retains the PDF in the existing bounded artifact cache and
creates stable dependent intents. Existing authenticated blob APIs upload only
the small deterministic original-source JSON body; the accepted primary PDF is
already owned by the service. Existing `research_file/original_source` publication
must succeed before the existing `reading_position` operation is sent. Known
retirement, changed parent lifetime, or conflicting source authority quarantines
unsent dependent positions. No PDF uploader, new endpoint, wire kind, SQL table,
native observation receipt, or AI/generation receipt is introduced.

Current primary C remains distinct from retained B. A received desktop position
may reuse its exact active applied SQL/wire owner and maintained inspectable
source, with real PDF page bounds, without inventing local native ownership. List
packages, independent backup, detached restore, and fresh package import are
tested with exact historical originals and a distinct current primary.

Strict backup also requires bytes named by historical document receipts. A fresh
peer missing an unrelated historical primary must fail before publication. The
fixture explicitly downloads that exact accepted receipt's blob through existing
authenticated bounded reads before retrying; no original-source authority is
created by that cache preparation.

## Private unsent recovery v2

Without position work, the existing v1 export retains its exact field order and
shape. Position work uses a closed v2 envelope with the sole required capability
`reading_position`, typed archives, and deduplicated PDF/body blobs. Total source
bytes are limited to 32 MiB, the serialized envelope to 64 MiB, metadata to 2 MiB,
and retained archives to 16. Oversize and invalid input fail without changing
state. The existing 128 MiB local artifact-cache quota still applies.

Each archived position records its exact owner, hash, observation, source
declaration, and historical accepted provenance. Source references distinguish
paper incarnations even when paper ID and PDF hash match. Retired or old-lifetime
data remains privately exportable; that evidence cannot authorize publication.
Old device, operation, request, and job identities remain archival. Existing v1
outbox, conflicts, ordinary drafts, and draft bases remain archive-only; there is
no generic v1 recovery replay or note importer.

Import independently checks the entire closed envelope, archive digests, exact
source bodies and PDF hashes, and real parser page bounds before one atomic
private cache/archive update. It changes no graph, outbox, cursor, credentials,
or current document. Repeat import preserves local review status. Re-export
preserves immutable original archives; review status belongs to the current
receiver, rather than conferring authority on a different device.

Explicit review requires the current authenticated binding. A different current
device in the same workspace is allowed only after it has independently received
the accepted source/document proof and the same current paper lifetime. Review
reparses exact bytes and captures current observations. An explicit entered save
then uses fresh request/source IDs and ordinary CAS; exported IDs are never
queued. Cross-workspace, retired-source, and stale-parent publication refuse.

At raw recovery/HTTP ingress the bounded structural scanner preserves the Python
integer-page boundary before `JSON.parse` erases forms such as `1.0`. Ordinary
JavaScript objects use safe-integer validation; they cannot distinguish `1` from
`1.0`. Legacy non-page numeric forms remain legal.

## Native reader resource fix and limits

The desktop projection index now closes its SQLite connection explicitly after
the existing commit/rollback context. A regression disables automatic GC and
performs an ordinary real `os.replace` before reader cleanup. This fixes the
reproduced projection-index WinError32 handle leak; it does not identify or claim
to fix the separate earlier papers-database WinError5 failure.

The native mobile `<object>` exposes neither page count nor viewport. Count proof
comes from the pinned offline PDF.js worker and exact verified bytes. A returned
page hint is not evidence of movement and does not guarantee a native viewer
jump. The isolated dialog is activated; combined integration/full-suite and
installed/physical-mobile acceptance remain separate gates.
