# Pending source comparison and reading state

The explicit Compare statements action can finish after ordinary persisted
reading-state writes when its complete scientific inputs are unchanged. This
local development integration is not a release or physical-device acceptance.

The producer remains strict by default. An explicit `reading_owner` permits a
worker-only recheck using the original process-sealed capture, original loaded
document and actual paper/workspace owner. After the one captured model response,
a stale physical lease can produce one new actual capture only if complete state,
saved outputs and source description/bytes still match. There is no additional
model request, retry loop, snapshot mutation, writer permission or paid fallback.
Changes during the final verification still fail safely.

The dialog preserves its original parent/view identity. A separate execution
capture and returned physical proof must be current at GUI delivery; the native
database and loaded PDF identity, selected route, cancellation and view lifetime
remain guarded. A pending write can defer the content judgment to the worker;
it never establishes equality on the GUI thread. Saving notes/references/highlights,
replacing/rebinding the database, changing source/account or cancelling cannot
install the old result. Stop retains any earlier temporary report while open.

A successful renewed report can navigate its exact original through the existing
read-only source verifier. Accepted close releases both original and renewed
captures after work drains, without GC. Source quotes, exact values and captured
requested/reported model metadata remain unchanged. Closed metadata is labeled
in English and Traditional Chinese; original quotations and identifiers stay literal.

Scope is deliberately bounded: this repairs physical interference during an
admitted comparison. New writes after an accepted report still invalidate its
strict lease and require reopening evidence before further generation/navigation.
It does not make every saved audit, appraisal, CLI job or idle report automatically
refreshable. External CLI reauthentication in an unchanged login directory remains
outside the captured settings witness. Temporary comparisons are not persisted,
synced, or certified as scientific truth.

Tests use actual isolated database/UI-state writes, real native file replacement,
held simulated completions, exact source navigation and weak references. No real
account, model service, daily research folder or deployment is used. The matching
integrated full gate and installed Windows/macOS/mobile acceptance remain separate.

## AI request disclosure

The configured output budget is an application request setting, not a verified
spending limit. The current CLI adapters do not forward an output-token limit;
the selected AI service controls actual generation and accounting. The comparison
view labels that distinction. Its one explicit Paperfact request is not a promise
of one vendor HTTP call or a billing cap. No automatic retry was added.

Gemini CLI responses without a parsed provider model identity retain the requested
identifier for compatibility but report the actual model as unknown. New consumers
use reported_model; this does not rewrite historical research or infer a version
from the request, service alias, usage data, or model catalog.
