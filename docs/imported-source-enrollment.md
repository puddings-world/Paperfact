# Imported originals during first enrollment

This adapter recognizes the lazy, closed receiver-local original ownership table
only in the trusted enrollment catalogue. Planning never creates that table.
Validated imported receipts use the existing source-owner envelope and explicit
150 MiB original-PDF policy; generated snapshots keep their 32 MiB default.

Enrollment preserves imported receipt observations in the private source archive
and complete backup. It resolves original bytes only through the fixed trusted
per-paper cache path, verifies hash and size, and stages a typed original-source
artifact for current claims. Imported owners are excluded from the new active
SQL database: source observations never become authority for another database,
device, lifecycle or pending job. The archived envelope remains byte-exact.
Only generated filesystem receipts join the receipt-file allowlist; imported SQL
rows do not authorize arbitrary files. Coverage reports include
`imported_source_receipts` separately from live research counts.

The focused fixture uses an actual unbound package import with claim source A
and current primary B, then prepares the first enrolled copy and independent
recovery backup. It checks source bytes, claim content, fresh lifecycle, no active
copied owner, wire privacy and detached recovery as nonreplayable observations.
Missing/corrupt originals, unknown files/tables/decks, cancellation and changed
receipt/source bytes must refuse publication.

This does not broaden unsupported live content or general history migration.
The version-2 list domain preserves a legacy `lists.note` SQL NULL explicitly,
separately from empty or whitespace text. The actual imported-list fixture now
requires a lossless NULL copy; peer/PWA/export/recovery coverage is described in
[Nullable list notes](nullable-list-notes.md). Older string-only validators must
update before receiving this additive version-2 domain value.

The source directory is unchanged, preparation does not adopt or upload the
candidate, and the combined release still requires the full project check.
