# Paperfact UX survey 2: library scale, AI chat, sharing, accessibility, import, background jobs (2026-10-31)

This continues `docs/ux-survey-2026-10.md` and does not repeat its topics (AI quote verification, reading↔notes, citation hover cards, graphs, onboarding, keyboard, progress, review, mobile, layers/export/search/drag/focus).
Effort: S = days, M = 1–3 weeks, L = more than a month. **[official]** = vendor docs/blog/changelog. **[3rd-party]** = library guide, review or forum, so treat with caution. **[unverified]** = I could not confirm it.

---

## 1. Library and list management at scale

| # | App | Pattern | Why it works (evidence) | Paperfact |
|---|---|---|---|---|
| 1.1 | **Zotero** [official] | Collections work like playlists (one item can sit in many, with no copy). Tags describe status or topic. Up to 9 **coloured tags**, each bound to a number key that toggles it on the selected items. Saved searches act as smart collections ("To Read" = tag is not "read"). | Status changes become one keystroke on a multi-selection, and a coloured square in the row shows status without opening anything. | Lists stay as they are. Add up to 9 coloured **status tags** (e.g. 精讀/略讀/待讀/引用) with keys 1–9 that work on a multi-selection in any list. **S** |
| 1.2 | **Paperpile** [official blog] | Built-in filters for "pilers": **Duplicates**, **Incomplete** (missing authors/DOI), **Not in folder / No label**. They can be combined (e.g. "no PDF" within one folder), and the filter panel can stay pinned. Labels and folders have bulk rename/recolour, **find-and-replace across names** and **merge similar labels**. | Clean-up becomes a filter you work through, not a hunt. | The library sidebar gets health filters: *No PDF*, *Unresolved metadata*, *Not in any list*, *Not analysed yet*, *Duplicates*. Each one is clickable and combinable with a list. **S–M** |
| 1.3 | **Readwise Reader** [official] | **Filtered views** are saved queries such as `minutes__lt:10 AND in:later` (Gmail-style, `field__op:value` with AND/OR). They can be pinned to the sidebar or Home and split into tabs by status. Shift+F creates one. The syntax guide is marked "work in progress". | "What to read next" is a query the user owns (short + queued + topic), not an opaque ranking. | A **"Next to read"** saved view per user: e.g. `status:待讀 list:X pages<15 has:pdf`, pinned to the Library home, sortable by added/year/length. Keep the bundled ML queue separate, as now. **M** |
| 1.4 | **Zotero / Paperpile / Raindrop** [official] | **Duplicates**: Zotero matches title/DOI/ISBN, year within ±1 and one author's surname + initial. Its merge picks a master and lets you choose each conflicting field, and it unions collections and tags. Zotero still cannot mark false positives and has no bulk merge. Paperpile adds **Merge all / Merge selected** and **"Not a duplicate"**, and sends the originals to Trash. Raindrop's Duplicates filter lists only the extra copies, so "delete all" is safe. | Users complain about exactly Zotero's gaps (bulk merge comes from a 3rd-party plugin, Zoplicate). Library guides warn about false positives (a conference paper vs. the journal version by the same authors). | A Duplicates view grouped by DOI/arXiv id/normalised title (reuse `openalex.same_paper` thresholds). Merge = pick a master, choose per-field values, **union lists, notes, highlights, analyses**, and keep the loser in Trash. Add a "Not a duplicate" pair memory. Treat the conference vs. arXiv version as a *link*, not a merge. **M** |
| 1.5 | **Zotero + Retraction Watch** [official blog 2019] | Retracted items get a banner, a warning when cited, an item-pane notice, and an auto "Retracted Items" virtual collection. The check runs privately without uploading the library. It covers retractions only, not expressions of concern. | Integrity signals appear without the user asking. | Optional: an "Erratum / retracted / newer version exists" badge from OpenAlex/arXiv version data on paper rows. **M** [Paperfact data source unverified] |

## 2. Chatting with AI about one or several papers

| # | App | Pattern | Why it works (evidence) | Paperfact |
|---|---|---|---|---|
| 2.1 | **NotebookLM / "Gemini Notebook"** [official help] | A **per-source checkbox** decides which sources answer the next question. **Save to note** pins a response with its tables and **clickable inline citations intact**, but the saved note is read-only. Plain copy drops the citations. **Configure Chat** sets the style (Default / Learning Guide / Custom) and the answer length. Chat history persists privately and can be deleted. Stop and "Keep generating" are available. | Scope is visible and set per question, and a kept answer keeps its evidence. Read-only saved answers keep the provenance honest. | 問 AI panel header: scope chips **[this paper] [+ selected papers] [whole list]** with a count. "Keep as note" stores the answer with live citations (page/anchor), **marked AI · read-only body**, with an editable user comment field under it. Per-task length/style presets go through `llm.complete` profiles. **M** |
| 2.2 | **Elicit Chat with Papers** [official help] | Chat over an explicitly selected set (max 8 paid / 4 free), drawn from one or more notebook steps. Toggle **full text vs. abstracts only** ("faster"). | A hard cap and a visible cost/speed switch stop the user from asking about 200 papers at once and getting vague answers. | Multi-paper scope: cap it (e.g. 8) with a message that says why. Add a "abstracts only (fast/cheap) / full text" toggle that shows the estimated token cost. **S–M** |
| 2.3 | **Beaver (Zotero plugin)** [3rd-party, developer forum post] | Hover a citation for a preview. Click to **open the PDF and highlight the passage**. Page- or sentence-level citations depending on mode. It runs in the reader sidebar and knows the current page. It syncs library data to its servers, which comparison guides flag as a privacy concern. | Evidence for click-to-highlight in a desktop reader. The cloud sync is the counter-lesson. | Already planned in survey 1 (#1). New point: say clearly **what leaves the machine** for each scope ("Sends: 3 papers' text to Claude via your login"). **S** |
| 2.4 | **Humata** [official homepage + 3rd-party reviews] | Each answer has page refs and **highlighted passages**. Follow-up questions on an indexed document come back in about 2 s (one reviewer). | Fast follow-ups come from indexing once per document, not per question. | Cache the extracted text and chunks of each paper once, so follow-ups in the same thread only send the question plus the retrieved chunks. **M** [latency claim unverified] |

## 3. Sharing in small groups without a server

| # | App | Pattern | Why it works (evidence) | Paperfact |
|---|---|---|---|---|
| 3.1 | **Zotero** [3rd-party forum, staff replies] | File → **Export PDF…** / reader **Save As…** writes a copy with the annotations embedded. Exporting without annotations gives the original file. A user reported that figures faded or disappeared after export (unconfirmed). | The receiver needs no app: any PDF viewer shows the highlights. | Bundle export option: **"PDFs with highlights burned in"** (own = yellow, AI = green, the user decides which layers to include) + notes as Markdown. Check figure rendering in a test fixture. **M** |
| 3.2 | **Readwise Reader** [official FAQ] | **Enable public link** on a document shows the highlights and annotations overlaid (not for PDF/EPUB). A filtered view can become a public **bundle** that refreshes. **Print / Download with annotations**. "Share highlight as image". | Several levels of sharing, from one quote to a whole curated set. | Share page (the existing read-only pocket page) = list + per-paper notes + highlights. Add "Share one highlight as image" (quote + title + page) for LINE/Slack, which is common in Taiwanese lab chats. **S–M** |
| 3.3 | **Hypothesis** [official research page + eLife] | Private/restricted groups for journal clubs. Members switch to the group in the sidebar and annotate as usual. The invite is a copied URL. | The low-friction invite is the point. It does need a server. | Serverless equivalent: export **"reading-group pack"** (.paperfact bundle: list + PDFs + each member's notes keyed by name). Import merges the pack as a **separate author layer** (colour per person) instead of overwriting. Comments become threads keyed by anchor. **M–L** |
| 3.4 | **Perusall** [3rd-party university guides] | Threads start from a highlight. Mark a comment as a question, or "same question" on someone else's. Check-mark upvotes, with instructor upvotes labelled. A **confusion report** aggregates open questions for the discussion leader. | For a reading group, the useful output is "which parts confused people". | When merging a group pack, show a **"Questions to discuss"** list: all notes tagged ❓ across members, sorted by count, each jumping to its anchor. **S** once 3.3 exists |

## 4. Accessibility and CJK reading

| # | App | Pattern | Why it works (evidence) | Paperfact |
|---|---|---|---|---|
| 4.1 | **Zotero 8** [3rd-party forum, staff replies] | Zotero 7 dark mode inverted the whole page, figures included. Staff said separating images was "highly complex". Zotero 8 added a **Black** theme and an **"Invert Images"** checkbox for custom themes. macOS has **View → Use Dark Mode for Content** (dark UI, light PDF). Users point to Acrobat's "background + text colour only" option. | Inverted heatmaps and plots mislead readers of ML papers, and this is a recurring complaint. | Reader theme menu: Light / Sepia / Dark (text only, **figures not inverted**) / Dark (invert all), plus "UI dark, page light". For PyMuPDF rendering, recolour by drawing the page with a colour matrix and then re-blit image bboxes untouched. **S–M** |
| 4.2 | **Sioyek** [official docs + GitHub discussions] | `custom_background_color` / `custom_text_color` plus a toggle command that can run at startup. A user complaint: it flattens **all** text colours, so coloured links and legends are lost. | Lesson: recolour only near-black text and near-white background, and keep chromatic colours. | Same as 4.1: map the luminance of greys only. Highlight colours must stay distinguishable in every theme (and have a non-colour cue, see survey 1 §1.3). **S** |
| 4.3 | **pangu.js / pangu.py / Obsidian Auto Spacer** [3rd-party, open source] | Insert a space at CJK–Latin boundaries (盤古之白). It is idempotent and skips code, links and tags. | Notes in Traditional Chinese with English terms (exactly Paperfact's deep dives) read better. Being idempotent means it is safe to run on save. | Display-time spacing in the note/analysis renderer (not a rewrite of stored text), with a toggle. Set the font stack explicitly: Latin font first, then **Noto Sans TC / Microsoft JhengHei / PingFang TC**, so Latin glyphs don't come from the CJK font. **S** |
| 4.4 | **Zotero 7** [official accessibility page + blog] | Tested with VoiceOver, NVDA and JAWS. It claims WCAG 2.2 AA (Oct 2024) and publishes a VPAT. EPUB font and size are adjustable. Beta-era forum reports showed NVDA could not read field labels. | Shows how much work this takes. The cheap part is labelled controls and keyboard reachability. | PySide6: set `accessibleName` on every icon button, keep a logical focus order, and scale the UI by the OS factor (plus an in-app 90–150% zoom for notes/analysis text). Full PDF screen-reader support: **skip for now** (see skip list). **S** |
| 4.5 | **Dyslexia tools (Helperbird, ReadEase)** [3rd-party] | Line/word/letter spacing, a reading ruler, saved profiles. A developer notes that the evidence for special dyslexia fonts is **mixed**. | Spacing and a ruler help more reliably than a special font. | The note/analysis view gets line-height and paragraph-spacing sliders. The ruler idea is already in survey 1 (focus mode). Don't bundle OpenDyslexic. **S** |

CJK name note [3rd-party forum]: Zotero sorts Chinese names correctly only under a Chinese UI locale and has no pinyin search. If Paperfact ever lists Chinese-authored papers, sort by a stored romanisation and search both forms. Low priority, since the corpus is mostly English.

## 5. Importing

| # | App | Pattern | Why it works (evidence) | Paperfact |
|---|---|---|---|---|
| 5.1 | **Paperpile** [official help] | BibTeX import offers **"Preserve citation keys"**. Keywords map to a keywords field, not to labels. The help page admits that malformed entries "may be skipped or imported with incomplete information". Batch **Auto-update** shows a progress window ending in a report: **updated / already up to date / no match**, with **"Show in list"**, which filters the library to the affected references for review. | The result report is the fix-up entry point. Nothing is silently half-imported. | `import-list` finishes with a report card: ✓ matched (n), ~ matched by fuzzy title (n, needs a glance), ✗ unmatched (n), ⚠ skipped/malformed (n). Each count is a button that filters the list to those rows. **S–M** |
| 5.2 | **Zotero** [3rd-party guides + forum] | **Add Item by Identifier** accepts several pasted DOIs, but all of one type. Mixed lists partly fail. "Retrieve Metadata for PDF" fails with "No matching references found", and the advice is "save from the article page" or **Create Parent Item** manually. File import has a "Place imported items into new collection" checkbox, and users asked for "into the selected collection" instead. | Pain points: mixed identifier lists, opaque failures, and the import destination. | One paste box that takes **any mix** of DOI / arXiv id / URL / title / BibTeX / plain citation lines. It classifies each line and shows its type before running. Destination picker: *new list / current list / no list* (Paperpile also lets you choose the destination at import). **M** |
| 5.3 | **Paperpile forum** [3rd-party] | Users complain that auto-update prefers **arXiv over the conference version** and that pasting BibTeX duplicates an existing entry instead of updating it. | Lets Paperfact avoid both. | Unmatched/fuzzy rows offer **candidate cards** (title, venue, year, source: S2/OpenAlex/arXiv) with "use this", "paste DOI", or "keep as citation only". If a match already exists in the library, offer "attach to existing" rather than creating a duplicate. Prefer the venue record and keep the arXiv one as an alternate link. **M** |
| 5.4 | **Paperfact MCP** (internal) | `imports.propose` → `imports.commit` with a stable operation_id. | Already the right shape: propose, review, commit, safe retries. | Reuse the same staged-import model for the UI importer, so the report card in 5.1 *is* the propose step and nothing is written until commit. **S** |

## 6. Feedback for long-running background AI jobs

| # | App | Pattern | Why it works (evidence) | Paperfact |
|---|---|---|---|---|
| 6.1 | **NotebookLM** [official blog + 3rd-party] | Audio generation runs in the background and you can keep working. It typically takes "a few minutes". Chat has Stop / "Keep generating". | Long jobs must not block the reading surface. | All analysis/slides/deep-dive jobs go into a **job tray** (status-bar icon with a count). The reader stays usable, and a toast with "Open" appears when a job finishes. **S–M** |
| 6.2 | **Zotero Find Available PDFs** [3rd-party forum] | Sequential processing of big selections takes hours. The progress window **hangs at "Processing"** for ~200–300 items, so users fall back to batches of 5–10. One user was **IP-banned** by a publisher and asked for throttling. | Counter-example: one modal progress list with no per-item state, no retry and no rate control. | Per-item rows (queued / running / done / failed: reason). **"Retry failed only"**. Cancel = stop after the current item. Explicit rate limiting and resuming the queue after a restart (the nightly `resolve-missing` already treats failures as non-final). **M** |
| 6.3 | **Elicit credits** [official help + 3rd-party] | Credits roughly track the amount of text processed. Monthly credits don't roll over. A 3rd-party summary says the estimate is "median-anchored", **"not a quote"**, and broad runs can cost more [unverified]. | An honest range before the run beats a surprise after it. | Before a batch ("Analyse 40 papers") show "~1.2–2.0 M tokens on profile *X* (Claude login)" from the local usage receipts, labelled as an estimate. Never present it as a bill (matches the CLAUDE.md rule). **S** |
| 6.4 | **Readwise Ghostreader BYOK** [official FAQ] | Uses a built-in default model without a key. With the user's own OpenAI key, other models can be picked. An insufficient-funds error says exactly that and suggests switching to a cheaper model. | Error messages that name the cause and the next step. | Map each `llm.complete` failure reason to a sentence + one action: "Claude login expired → 重新登入", "quota hit → retry at 14:00 / switch profile". Failed jobs stay in the tray with that action. **S** |

## Ranked top-8 (impact for a researcher ÷ effort)

1. **Import report card + fix-up queue** (Paperpile updated/current/no-match + "Show in list"; Zotero failure lessons). Counts that filter the list, candidate cards for fuzzy/unmatched rows, "attach to existing", destination picker, built on propose/commit. *Import.* **S–M**
2. **Job tray for background AI** (NotebookLM non-blocking; Zotero hang counter-example; Ghostreader errors). Per-item status, cancel, retry-failed-only, resume after restart, failure reason + one action. *Global status bar.* **S–M**
3. **Coloured status tags with keys 1–9 + bulk actions on multi-select** (Zotero). Fastest triage win across many lists. *Library.* **S**
4. **Ask-AI scope chips + "Keep as note" with live citations** (NotebookLM checkboxes / Save to note; Elicit cap + abstracts-only toggle). *問 AI panel.* **M**
5. **Dark reading theme that doesn't invert figures** (Zotero 8 Invert Images; Sioyek colour-flattening complaint). Recolour greys only, plus a "UI dark / page light" option. *Reader.* **S–M**
6. **Duplicates view with merge that unions notes/highlights + "Not a duplicate"** (Zotero field picker, Paperpile Merge all, Raindrop extras-only list). *Library.* **M**
7. **Saved "Next to read" views + library health filters** (Readwise filtered views; Paperpile Incomplete/No-folder filters). *Library home.* **M**
8. **Annotated-PDF export + one-highlight image share** (Zotero Export PDF; Readwise public link / share-as-image). The first step toward reading-group packs. *Export.* **S–M**

Honourable mentions: CJK–Latin auto-spacing + explicit TC font stack in notes (**S**). Pre-run token estimate labelled "estimate" (**S**). Reading-group pack with per-member layers and a "Questions to discuss" list (**M–L**). Accessible names and focus order on PySide6 controls (**S**).

## Skip list

- **Server-backed group annotation** (Hypothesis groups, Zotero group libraries): needs identity and hosting, which are still gated in v0.5. Use file-based packs instead.
- **Classroom features from Perusall** (grading, minimum-annotation quotas): this is a course tool, not a lab reading group.
- **Library-wide agentic chat that uploads the whole library** (Beaver-style cloud sync): a privacy and quota cost. Keep scope explicit and capped.
- **Full screen-reader access to PDF content**: QPdfView/PyMuPDF expose no accessible text layer. That is an L effort, so do labelled controls and the reflow/notes view first.
- **Bundling a dyslexia font**: the evidence is mixed. Spacing controls give more for less.
- **Automatic metadata overwrite** ("auto-update" without review): Paperpile users report arXiv records replacing conference records. Always stage changes.
- **Retraction badges** until a reliable free data source is confirmed for ML venues [unverified].

## Not verified / caveats

- NotebookLM's official help now calls the product "Gemini Notebook". Whether the button reads "Save to note" or shows a pin icon differs between guides.
- The Elicit 8/4 paper cap comes from an undated help article. "Estimate is not a quote" is from a 3rd-party MCP listing.
- Humata latency and Beaver's citation behaviour come from reviews and the developer's own forum post. I could not find ChatPDF/SciSpace/Consensus docs on follow-up threads, so they are omitted.
- Whether Zotero 8 "Invert Images" has shipped in a stable release (forum staff described it in beta). The figure loss after Zotero PDF export is one unconfirmed user report.
- Readwise's public link excludes PDFs. Whether "Download with annotations" applies to PDFs is per the FAQ, but I did not test it.
- I could not find the Sioyek shared-database sync, Mendeley duplicate UX, or Papers/ReadCube shared collections docs.
